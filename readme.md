# Atuko

**Atuko** (Yoruba: "driver") is a Chrome MV3 browser automation extension built for engineers. Also called **Flōw** internally.

Record, build, and run multi-step workflows directly in Chrome — no external tools, no cloud dependency, no account required. Every workflow compiles to portable, human-readable JSON that you can version-control, share, or generate programmatically.

---

## Features

### Workflow Builder
- Drag-and-drop step canvas with a step inspector panel
- Visual branch and loop editors with inline condition builders
- Variable binding UI for all step fields that support `{{var}}` interpolation

### Action Recorder
- Click the record button and interact with any page
- Auto-detected wait gaps: if you pause for 5 seconds between actions, a `wait` step is automatically inserted with `waitType: "duration"`
- Generates stable CSS and XPath selectors with fallbacks and stability scores for every recorded element

### 18 Step Types
`click`, `fill`, `wait`, `scroll`, `navigate`, `submit`, `select`, `hover`, `keypress`, `extract`, `screenshot`, `tab`, `clipboard`, `storage`, `log`, `prompt`, `setVariable`, `branch`, `loop`, `stop`, `jump`

### Element Picker
- Crosshair mode for manual selector targeting
- Generates primary + fallback selectors automatically
- Assigns a stability score (0–1) to each generated selector
- Text-based selectors: targets buttons and links by visible label, e.g. `xpath=//button[normalize-space()='Log in']`

### Variable System
- 4 scopes: `run`, `workflow`, `site`, `global`
- Built-in read-only variables: `$url`, `$title`, `$timestamp`, `$date`, `$time`, `$runId`, `$stepIndex`, `$iteration`, `$item`
- Interpolation syntax: `{{variableName}}` in any string field

### Site Config
- Per-domain selector aliases (reference any selector as `@alias-name`)
- Network intercept rules: read or modify network responses before they reach the page
- Shared workflow-scope variables per hostname

### Run History
- Full step-level logs for every run
- Output capture and extracted variable values
- Per-step screenshot history

### Live Toast Overlay
- Injected into the active tab via shadow DOM
- Shows current step name, progress indicator, and pause/stop controls
- Non-intrusive 300px bottom-right overlay

### Import / Export
- Every workflow is plain JSON — export and import via the builder UI
- Workflows can be generated by AI agents and imported directly

### Dry Run Mode
- Simulates a full workflow run without touching the DOM
- Validates selectors, variable references, and step logic before executing

## Architecture

### Extension Surfaces

| Surface | Entry | Description |
|---|---|---|
| Side Panel | `src/features/builder` | Full workflow builder React SPA |
| Popup | `src/features/popup` | Runtime dashboard, 360px wide, max 600px tall |
| Options Page | `src/features/options` | Extension settings |
| Toast | `src/features/toast` | Injected shadow DOM React root, 300px, bottom-right |

### Background Contexts

| Context | Description |
|---|---|
| Service Worker | Orchestration engine, message router, run state machine |
| Content Script | DOM step executor, element picker, recorder |

### Message Flow

```
Side Panel / Popup
    → chrome.runtime.sendMessage
        → Service Worker
            → chrome.tabs.sendMessage
                → Content Script
                    → chrome.runtime.sendMessage
                        → Service Worker
                            → Side Panel / Popup
```

### Storage

| Store | Used For |
|---|---|
| `chrome.storage.local` | Workflows, run history, site configs, all variable scopes except sync |
| `chrome.storage.sync` | Extension settings only |

### Tech Stack

- **React 18** + **TypeScript** (strict, `noImplicitAny`)
- **Vite** + **@crxjs/vite-plugin** (multi-entry: popup, side-panel, options, service-worker, content-script)
- **Tailwind CSS v4**
- **TanStack Query** for side panel data fetching
- **Lucide React** via `@shared/ui/icons` proxy (never import Lucide directly in feature code)
- **Inter** font for UI, **JetBrains Mono** for code, JSON, and selectors
- Path aliases: `@app` → `src/`, `@features` → `src/features/`, `@shared` → `src/shared/`, `@ui` → `src/ui/`

## Workflow JSON Schema

This section is the authoritative reference for the Atuko workflow JSON format. AI agents generating workflows should follow this schema exactly.

### Top-Level Workflow Object

```ts
{
  id: string;           // UUID v4
  name: string;         // Display name
  description: string;  // Optional description
  site: string;         // Hostname e.g. "example.com" (no protocol, no path)
  version: number;      // Always 1
  enabled: boolean;     // Whether the workflow can be triggered automatically
  triggers: TriggerObject[];
  steps: StepObject[];
  variables: Record<string, string>; // Default workflow-scope variable values
  tags: string[];
  createdAt: string;    // ISO 8601
  updatedAt: string;    // ISO 8601
}
```

---

### Trigger Types

#### ManualTrigger
```json
{ "type": "manual" }
```

#### UrlMatchTrigger
```json
{
  "type": "url-match",
  "pattern": "https://example.com/login*",
  "matchType": "glob",
  "matchOn": "load",
  "once": false,
  "delay": 0
}
```

| Field | Type | Values |
|---|---|---|
| `pattern` | string | The URL pattern to match against |
| `matchType` | string | `"glob"` \| `"exact"` \| `"prefix"` \| `"regex"` |
| `matchOn` | string | `"load"` \| `"domcontentloaded"` \| `"urlchange"` |
| `once` | boolean | Only fire once per page visit |
| `delay` | number | Milliseconds to wait after match before starting |

#### ChainTrigger
```json
{
  "type": "chain",
  "workflowId": "uuid-of-parent-workflow",
  "onStatus": "success",
  "passVariables": ["authToken", "userId"]
}
```

| Field | Type | Description |
|---|---|---|
| `workflowId` | string | UUID of the parent workflow that triggers this one |
| `onStatus` | string | `"success"` \| `"any"` |
| `passVariables` | string[] | Variable names to inherit from the parent run |

### Step Base Fields

Every step type includes these fields:

```ts
{
  id: string;          // UUID v4 — must be unique within the workflow
  type: string;        // Step type (see below)
  label: string;       // Human-readable step name
  note?: string;       // Optional comment, not used at runtime
  enabled: boolean;    // Set to false to skip this step without deleting it
  onError: "stop" | "skip" | "retry" | "branch";
  retries: number;     // 0–5
  retryDelay: number;  // Milliseconds between retries
}
```

---

### SelectorObject

Used anywhere a DOM element must be targeted.

```ts
{
  primary: string;        // The main selector to try first
  fallbacks: string[];    // Ordered list of fallback selectors
  stabilityScore: number; // 0.0–1.0, higher = more stable
}
```

**Supported selector formats:**

| Format | Example | Notes |
|---|---|---|
| CSS id | `#submit-btn` | Stability ~0.95 |
| CSS data-testid | `[data-testid="login-btn"]` | Stability ~0.95 |
| CSS class | `.btn-primary` | Stability ~0.6 |
| CSS attribute | `[aria-label="Close"]` | Stability ~0.8 |
| XPath bare | `//button[@id='x']` | Bare XPath, starts with `//` |
| XPath prefixed | `xpath=//button[normalize-space()='Log in']` | Explicit xpath= prefix |
| Site alias | `@login-button` | Resolved from site config selector aliases |

**Stability score guidance:**
- `0.95` — `[data-testid]`, `#id`
- `0.85` — `[aria-label]`, `[name]`, `[placeholder]`
- `0.75` — XPath text match (`normalize-space()`)
- `0.6` — CSS class
- `0.4` — positional XPath (`//div[3]/button[1]`)

### Step Types

#### click
Click a DOM element.

```json
{
  "id": "step-uuid",
  "type": "click",
  "label": "Click submit",
  "enabled": true,
  "onError": "stop",
  "retries": 0,
  "retryDelay": 500,
  "selector": { "primary": "[data-testid='submit']", "fallbacks": [], "stabilityScore": 0.95 },

  "waitBefore": 0,
  "scrollIntoView": true,
  "force": false
}
```

| Field | Type | Description |
|---|---|---|
| `selector` | SelectorObject | Target element |
| `button` | string | `"left"` \| `"right"` \| `"middle"` |
| `doubleClick` | boolean | Double-click instead of single click |
| `waitBefore` | number | Milliseconds to wait before clicking |
| `scrollIntoView` | boolean | Scroll element into viewport before clicking |
| `force` | boolean | Click even if element is not visible |

### ConditionObject

Used in `branch` and `loop` steps.

```ts
{
  type: "variable" | "element-exists" | "element-missing" | "element-text" | "element-value" | "url-matches" | "response-contains";
  selector?: SelectorObject;  // For element-* types
  variable?: string;          // For type: "variable"
  operator: "equals" | "not-equals" | "contains" | "not-contains" | "starts-with" | "ends-with" | "greater-than" | "less-than" | "is-empty" | "is-not-empty";
  value?: string;             // The value to compare against
  pattern?: string;           // For type: "url-matches"
  responseVar?: string;       // For type: "response-contains"
}
```

### Variable Scopes

| Scope | Lifetime | Shared Across |
|---|---|---|
| `run` | Current run only | Nothing — cleared when run ends |
| `workflow` | Persistent | Runs of this specific workflow |
| `site` | Persistent | All workflows on the same hostname |
| `global` | Persistent | All workflows on all sites |

Variables are interpolated in string fields using `{{variableName}}`.
Built-in variables use a `$` prefix: `{{$url}}`, `{{$runId}}`, etc.

### Built-In Variables (Read-Only)

| Variable | Value |
|---|---|
| `{{$url}}` | Current tab URL |
| `{{$title}}` | Current page title |
| `{{$timestamp}}` | Unix timestamp in milliseconds |
| `{{$date}}` | Current date as `YYYY-MM-DD` |
| `{{$time}}` | Current time as `HH:MM:SS` |
| `{{$runId}}` | UUID of the current run |
| `{{$stepIndex}}` | 0-based index of the current step |
| `{{$iteration}}` | Current iteration count inside a loop |
| `{{$item}}` | Current item in a `for-each` loop |

## AI Agent Usage

Atuko workflows are designed to be machine-generated. Any AI agent can produce a valid workflow by following the JSON schema above.

### Getting Started
1. Generate a valid workflow JSON following the schema in this document
2. Open the Atuko side panel in Chrome
3. Click **Import** and paste your JSON

### Schema Guarantees
- Every field is typed and validated at import time
- The JSON is fully deterministic — no ambiguous fields
- Every step requires `id`, `type`, `label`, `enabled`, `onError`, `retries`, and `retryDelay` in addition to its type-specific fields

### Selector Strategy (most to least stable)
1. `[data-testid="x"]` — stability ~0.95, preferred when available
2. `#id` — stability ~0.95, use when ID is semantic (not auto-generated)
3. `[aria-label="x"]` — stability ~0.85
4. `[name="x"]` or `[placeholder="x"]` — stability ~0.85
5. `xpath=//button[normalize-space()='Label']` — stability ~0.75, best for buttons and links by visible text
6. `.class-name` — stability ~0.6, use only when class is semantic
7. Positional XPath `(//div[@class='x'])[2]` — stability ~0.4, last resort only

Always include at least two fallback selectors. For buttons and navigation links, the XPath text selector is the most resilient across refactors.

### Wait Strategy
- Prefer `waitType: "element"` over `waitType: "duration"` — it is faster and more resilient to variable page load times
- Use `waitType: "duration"` only when waiting for animations or non-DOM state
- Always set a `timeout` on wait steps and decide what `onTimeout` should do

### Variable Interpolation
- Any string field can contain `{{variableName}}` which is resolved at runtime
- Define default values in the workflow's top-level `variables` object
- Use `setVariable` steps to compute derived values from extracted content
- The `setVariable` transform `"json-parse"` is useful when extracting JSON-encoded data from the DOM or storage
